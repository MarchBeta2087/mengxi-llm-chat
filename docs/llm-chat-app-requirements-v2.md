## 1. 项目概述

### 1.1 项目背景

"梦溪畅谈"（mengxi-llm-talk）是一个可自部署的 LLM 聊天 Web 应用，支持多模型、多 API Key 管理、可扩展插件体系，面向"管理员提供公共服务 + 用户可接入自有密钥"的使用场景。名称源自沈括《梦溪笔谈》——取"笔谈"之"记录"与"畅谈"之"对谈"双关，恰合本应用"加密聊天记录 + AI 对谈"的产品形态。

### 1.2 设计目标

- **简洁可定制**：界面布局与颜色可自由调节，提供多套预设主题。
- **密钥安全**：API Key 以 AES-256-GCM 加密存储于数据库，主密钥与数据库分离。
- **对话隐私**：对话内容落库前加密，数据库泄露不泄露聊天内容。
- **公私双轨**：公有 Key 由管理员维护、全员可用；私有 Key 由用户自行维护、仅本人可用，调度时私有优先。
- **精细限流**：每条 Key 独立支持 RPM / RPH / RPD / TPM / TPH / TPD 六维速率限制。
- **插件化**：插件分全局插件（强制生效）与可选插件（用户自行启用），支持按用户组批量配置。

### 1.3 非目标（Out of Scope）

- 不实现模型训练 / 微调功能。
- 不提供官方托管服务（本项目仅面向自部署）。
- 多副本水平扩展在第一版不强制要求，但架构不得阻塞后续扩展。
- 端到端加密（E2EE）聊天模式：远期目标，v1 不做（见 §4.8.3）。

## 2. 术语定义

| 术语 | 定义 |
| --- | --- |
| 公有 Key | 由管理员配置、对所有用户可见可用（脱敏展示）的上游 API Key |
| 私有 Key | 由普通用户自行配置、仅本人可见可用的上游 API Key |
| 主密钥（KEK） | 用于加解密所有 API Key 密文与对话内容密钥的根密钥，不落数据库 |
| DEK | 数据加密密钥：DEK_key（加密 API Key）、DEK_conv（加密对话内容，按用户） |
| 恢复码 | 档 A 主口令遗忘时用于重新获取 KEK 的一次性代码 |
| 全局插件 | 管理员添加、对所有用户强制生效、不可禁用的插件 |
| 可选插件 | 管理员添加、默认状态可配置、用户可自行启停的插件 |
| 用户组 | 管理员定义的用户集合，可批量设置插件默认状态与配额 |
| 六维限流 | RPM、RPH、RPD、TPM、TPH、TPD |

| 能力 | 匿名用户 | 普通用户 | 管理员 |

| 添加 / 管理私有 Key | ❌ | ✅（仅本人） | ✅ |
| 查看 Key 明文 | ❌ | ❌（仅本人 Key 的脱敏形式） | ❌（公有 Key 配置时可见，此后仅脱敏） |
| 配置公有 Key | ❌ | ❌ | ✅ |
| 添加 / 管理插件（两种） | ❌ | ❌ | ✅ |
| 启用 / 禁用可选插件 | ❌ | ✅（仅本人） | ✅ |
| 按用户组批量配置插件默认状态 | ❌ | ❌ | ✅ |
| 设置用户 / 用户组日配额 | ❌ | ❌ | ✅ |
| 查看审计日志 | ❌ | 仅本人记录 | ✅ |
| 自定义界面布局 / 颜色 | ❌ | ✅（仅本人） | ✅（并可设置全局默认） |

\* 匿名用户是否可用公有 Key 由管理员开关控制；若开放，必须叠加 IP 级限流与验证码等防刷手段（见 §9.3）。

**核心隐私承诺**：
1. 任何角色（包括管理员）无法查看其他用户的私有 Key 明文；管理员后台仅展示私有 Key 的元数据与用量统计。
2. 管理员无法直接读取用户对话内容明文（数据库中均为密文；运行期内存中的解密权限属于系统内部，不提供任何管理界面访问入口）。

## 4. 功能需求

### 4.1 密钥管理

**4.1.1 基本能力**
- 支持添加不限条数的 API Key，每条可独立配置：展示名、`base_url`、模型列表（支持通配如 `gpt-*`）、六维限流值（0 或留空 = 不限）、启用状态。
- 支持编辑、删除、启停、连通性测试（服务端发起真实探测请求并计入消耗）。

**4.1.2 存储加密**
- 所有 API Key 以 AES-256-GCM 加密存储；每条记录独立随机 IV（12 字节），密文、IV、auth tag 合并存于 `encrypted_key` 字段。
- 数据库中不存在任何明文 Key；日志、错误信息、调试输出必须脱敏拦截。
- 主密钥采用信封加密方案（KEK 加密各类 DEK，DEK 加密数据）。

**4.1.3 主密钥派生（三档可选）**

| 档位 | 方案 | 适用场景 |
| --- | --- | --- |
| A（完整） | 管理员口令经 Argon2id 派生 KEK；随机 DEK 由 KEK 加密后落盘（权限 600）；重启后需重新输入口令解锁；**提供恢复码机制**（§4.1.6） | 单实例自部署，安全性最高 |
| B（折中） | 主密钥存于 `.env` 文件（权限 600），接受"读文件系统即可解密"的威胁模型 | 轻量部署 |
| C（生产） | 外部 KMS（AWS KMS / Vault）托管 KEK，应用侧仅缓存 DEK | 生产环境、多实例 |

约束：KEK 不得写入数据库、不得进入日志；支持密钥轮换流程（重新加密 DEK / 密文迁移）。

**4.1.4 SSRF 防护（强制）**
1. 仅允许 `https:`；`http:` 仅管理员可配置（用于 Ollama 等局域网服务）。
2. 请求前解析目标域名并对**实际连接的对端 IP** 校验（防 DNS 重绑定），拒绝：回环、私网、链路本地（含云元数据地址 `169.254.169.254`）及其 IPv6 等价范围。
3. 管理员可配置可选域名白名单。
4. 重定向每一跳重新校验。

**4.1.5 展示与脱敏**
- 接口不回传 Key 明文，仅返回 `sk-...abcd`（前 4 + 后 4）。
- 私有 Key 列表仅 owner 可见；管理员只见元数据与用量。

**4.1.6 恢复码机制（档 A，v2 决策）**
- 管理员首次设置主口令时，系统生成 **8 个一次性恢复码**（CSPRNG，格式 `XXXX-XXXX-XXXX`）。
- 恢复码**只展示一次**，前端强制用户确认已保存后才允许继续。
- 存储方式：每个恢复码的标识（HMAC-SHA256(恢复码)）与"用该恢复码加密的 KEK 副本"入库；恢复码明文与 KEK 明文均不落盘。
- 使用：任一恢复码可解密 KEK 副本 → 重置主口令并重新派生 KEK → 该恢复码立即作废，同时作废其余全部恢复码并生成新一批（防止同一泄露批次被重复使用）。
- 管理员后台可随时重新生成全部恢复码（旧码即刻失效）。

### 4.2 密钥调度

```
请求到达
  ├─ 1. 用户有 active 私有 Key 且模型匹配？
  │      ├─ 是 → 私有池按"剩余配额加权轮询"选择
  │      │      ├─ 全部限流/熔断/耗尽 → 视配置回退公有池或报错
  │      │      └─ 转发上游
  │      └─ 否 → 2
  └─ 2. 公有池按"剩余配额加权轮询"选择
         └─ 全部不可用 → 返回明确错误提示
```

- **熔断**：连续 401 / 429 / 5xx 达阈值后暂时摘除，冷却结束自动探测恢复。
- **失败回退（v2 决策：UI 弹窗提示）**：私有触发 429 时是否回退公有，由管理员全局配置；回退发生时**前端弹出提示**（"您的私有 Key 已触发限流，本次请求已使用公共 Key 转发"），响应头同步携带 `X-Fallback-To-Public: 1` 以便前端判断。
- **配额感知**：优先调度剩余额度比例最高的 Key，避免单 Key 先被打爆。

### 4.3 速率限制

- 六维独立配置：RPM / RPH / RPD / TPM / TPH / TPD，0 或空 = 不限。
- 计数存于 Redis：`ratelimit:{key_id}:{dimension}:{window_start}`（INCR + EXPIRE）。
- 请求时六维逐一检查，任一超限即拒绝（返回 429 并指明维度）。
- Token 计数以 provider 响应的 `usage` 字段为准，不做本地估算。
- **三层兜底**：Key 级 → 用户级 → IP 级。
- **用户日配额（v2 决策）**：管理员可对单个用户或用户组设置每日 Token 消耗上限（0 = 不限），跨该用户使用的所有 Key 汇总计算，超限返回 429 并提示"今日配额已用完"。

### 4.4 插件系统

**类型划分**

| 类型 | 添加者 | 生效范围 | 用户控制 |
| --- | --- | --- | --- |
| 全局插件 | 管理员 | 所有用户强制生效 | 不可禁用 |
| 可选插件 | 管理员 | 按需 | 用户启停；管理员可设默认启用/禁用 |

- 插件来源仅官方内置或管理员上传；不允许用户自行安装远程插件。

**用户组批量配置（v2 决策，允许）**
- 管理员定义用户组（`user_groups`），将用户加入组。
- 生效优先级（从高到低）：
  ```
  全局插件（强制） > 用户组插件配置 > 用户个人设置 > 插件默认状态
  ```
- 示例：管理员将"研发组"的可选插件 `code-runner` 设为组内默认启用，则该组新用户无需手动开启；用户个人仍可在组配置范围内覆盖。

**Manifest 示例**

```json
{
  "name": "web-search",
  "version": "1.2.0",
  "description": "联网搜索",
  "type": "global | optional",
  "permissions": ["http:outbound", "web_search"],
  "default_state": "disabled",
  "runtime": { "timeout_ms": 10000, "memory_mb": 128 }
}
```

**运行隔离**
- 插件运行于独立进程 / WASM 沙箱，与主进程内存隔离，无法访问数据库连接、其他用户会话、任何 Key 明文、任何对话明文（即使解密后也在会话层隔离）。
- 权限声明制：启用时向用户展示所需能力，运行时宿主拦截越权调用。
- 资源限制：默认超时 10s、内存 128MB。
- **注入防护**：插件返回值标记为不可信内容，注入对话前做边界包装。

### 4.5 聊天功能（基础）

- 多会话管理（新建、重命名、删除、归档）、流式输出（SSE）。
- 可选模型列表由"当前可用 Key 池支持范围"动态计算。
- 界面布局（侧边栏位置、宽度、密度）与颜色（主题色、深浅模式）自由调节，多套预设主题。

### 4.6 管理后台

- 公有 Key 管理（增删改、启停、限流配置、用量图表）。
- 插件管理（上传、配置、全局/可选切换、默认状态、**按用户组批量配置**）。
- **用户与用户组管理**（封禁、查看用量、设置日配额）。
- 系统设置：匿名访问开关、私有回退公有开关、域名白名单、全局默认主题。
- 审计日志检索；主密钥状态查看（是否解锁、KEK 档位、恢复码剩余数量、最近轮换时间）。

### 4.7 审计日志

每次上游调用记录：

```
{ timestamp, user_id, key_id, key_type(public/private), model,
  base_url_host, tokens_in, tokens_out, latency_ms, status,
  fallback_to_public, client_ip }
```

- v2 新增 `fallback_to_public` 字段，记录本次请求是否发生了私有→公有回退，供审计与告警。
- 普通用户仅查本人记录；管理员可查全部。
- 默认保留 90 天，可配置；**不记录对话内容**，所有 Key 字段脱敏。

### 4.8 对话记录加密（v2 新增）

**4.8.1 总体方案：服务端静态加密（默认启用，不可关闭）**

- 消息 `content` 在写入数据库前以 AES-256-GCM 加密；读取时在服务内存中解密后返回。
- **密钥体系**：与 API Key 共用信封加密基础设施。
  - 每个用户注册时生成随机 `DEK_conv`（对话内容密钥）。
  - `DEK_conv` 由系统主密钥 KEK 加密后存储于 `users.conversation_key_encrypted`。
  - 每条消息使用独立随机 IV，密文格式 `iv || ciphertext || tag`。
- 会话内密钥缓存：解密后的 `DEK_conv` 在服务内存中缓存（带 TTL 与容量上限的 LRU），避免每条消息都解密一次密钥。
- 管理员**没有任何界面或接口**可以读取用户对话明文；解密能力仅供聊天服务自身在转发上游时内部使用。

**4.8.2 加密带来的功能适配**

| 功能 | 影响 | 对策 |
| --- | --- | --- |
| 全文搜索历史会话 | 密文无法 LIKE | 加密会话使用盲索引（HMAC-SHA256(content_key, 关键词) 建立关键词指纹表）；或管理员可选关闭"加密会话搜索"功能，仅标题可搜 |
| Token 统计 | 无影响 | 以 `usage` 字段为准，发生在解密前 |
| 会话标题 | 低敏感 | 标题默认不加密（可配置为加密） |
| 上下文拼接 | 无影响 | 服务端解密后在内存中拼接发送上游 |
| 备份 | 只含密文 | 与 API Key 同标准保护 |

**4.8.3 远期规划：E2EE 敏感会话模式（v1 不做）**

- 远期可提供"敏感会话"开关：消息在浏览器端用用户 passphrase 派生的密钥加密，服务端终生不见明文。
- 代价：服务端无法代发上游（需客户端直连或浏览器内解密后自行调用），与密钥池调度、限流、审计、插件冲突。
- 决策：v1 不做，仅在此声明为路线图项目；v1 的静态加密已覆盖"数据库/备份泄露"这一主要威胁。

### 4.9 用户与用户组配额

- 配额维度：每日 Token 消耗上限（`daily_quota_tokens`，0 = 不限）。
- 作用范围：可应用于单个用户或用户组；用户个人设置优先于组设置。
- 计数：Redis `quota:{user_id}:{date}`（INCR + 当日过期），请求完成后按 `usage` 精确累计。
- 超限行为：拒绝新请求，返回 429 + 友好提示；已进行中的流式请求不打断。

## 5. 非功能需求

- **安全**：全站 HTTPS；会话 Cookie `HttpOnly + Secure + SameSite=Lax`；密码 Argon2id；登录防爆破；参数化查询防注入；备份只含密文（API Key 密文 + 对话密文）；依赖漏洞扫描纳入 CI。
- **性能**：首 token 延迟（不含上游）< 2s；限流检查开销 < 5ms；对话解密开销 < 3ms/条（密钥缓存命中）；4C8G 单实例支撑 ≥ 200 并发会话。
- **可用性**：档 B/C 重启自动恢复；档 A 提供明确的"待解锁"提示页；上游故障时熔断 + 池内回退；恢复码机制保证档 A 不因口令遗忘而永久失锁。
- **可维护性**：Docker Compose 一键部署（应用 + Redis + PostgreSQL）；版本化迁移脚本；配置项可由环境变量覆盖。
- **数据库**：**PostgreSQL 为唯一官方支持数据库**（v2 决策）；不再维护 SQLite 兼容代码路径。

## 6. 数据模型（核心表）

```sql
users(
  id, username, password_hash, role, status,
  conversation_key_encrypted,      -- DEK_conv 密文(KEK加密)
  daily_quota_tokens,              -- 0 = 不限
  group_id NULL,
  settings_json, created_at
)

user_groups(id, name, daily_quota_tokens, settings_json)   -- 组级配额与配置

api_keys(
  id, user_id NULL,                -- NULL = 公有
  provider_name, base_url,
  models_json,                     -- ["gpt-4o", "claude-*"]
  encrypted_key,                   -- AES-256-GCM(iv||ciphertext||tag)
  rate_limits_json,                -- {rpm,rph,rpd,tpm,tph,tpd}
  weight, status,
  priority_pool,                   -- public / private
  last_used_at, usage_json, created_at, updated_at
)

recovery_codes(
  id, code_hash,                   -- HMAC-SHA256(恢复码)
  kek_encrypted,                   -- 该恢复码加密的 KEK 副本
  used_at NULL, created_at
)

plugins(id, name, version, manifest_json, type, default_state, status)

user_plugins(user_id, plugin_id, enabled)        -- 用户个人覆盖
group_plugins(group_id, plugin_id, state)        -- 用户组批量配置 (v2)

conversations(id, user_id, title, model, encrypted BOOLEAN, created_at, archived)
-- title 默认明文; encrypted=1 的会话其消息体均为密文

messages(
  id, conversation_id, role,
  content_encrypted,               -- AES-256-GCM(iv||ciphertext||tag)，密钥=该用户的 DEK_conv
  tokens_in, tokens_out,           -- 明文统计，解密前完成
  blind_index NULL,                -- 可选关键词指纹（加密会话搜索）
  created_at
)

message_keywords(message_id, keyword_fp)         -- 盲索引表（HMAC指纹，不含明文）

audit_logs(
  id, user_id, key_id, key_type, model, base_url_host,
  tokens_in, tokens_out, latency_ms, status,
  fallback_to_public,              -- v2
  client_ip, created_at
)
```

## 7. 关键流程

**7.1 聊天请求**

```
用户请求 → 鉴权 → 用户日配额检查(Redis)
  → 模型匹配 Key 池 → SSRF 校验(连接时)
  → Redis 六维限流检查(通过→占位计数)
  → 选择最优 Key → 解密历史上下文(DEK_conv, 缓存)
  → 转发上游(流式) → 收到 usage → 精确记账(限流+日配额+审计)
  → 回复内容 AES-GCM 加密落库(独立IV)
  → 返回用户
  → 失败时按熔断/回退策略重试或报错(回退时前端弹窗提示)
```

**7.2 主密钥解锁（档 A）**

```
服务启动 → 检测 DEK 文件存在?
  ├─ 存在 → 进入"待解锁"状态，管理页提示输入口令
  │         → Argon2id(口令, salt) = KEK → 解密 DEK → 服务就绪
  ├─ 不存在 → 引导管理员设置口令 → 生成 KEK/DEK → 加密 DEK 落盘
  │            → 展示 8 个恢复码(仅一次) → 确认后进入服务
  └─ 遗忘口令 → 输入任一恢复码 → 解密 KEK 副本 → 重置口令
                → 旧恢复码全部作废 → 生成新一批恢复码
```

**7.3 插件生效状态解析（单个用户）**

```
插件 state = 全局插件            → 强制启用
           组配置了该插件        → 采用组配置
           用户个人有覆盖        → 采用用户设置
           否则                  → 插件默认状态
```

## 9. 威胁模型与防护

| 威胁 | 防护 |
| --- | --- |
| 数据库泄露（Key） | 密文 + KEK 不落库；备份同等保护 |
| 数据库泄露（对话内容） | v2：消息体 AES-256-GCM 密文 + 按用户 DEK_conv；盲索引不含明文 |
| 主口令遗忘（档 A） | 恢复码机制（一次性、用后全量轮换） |
| 恶意 base_url（SSRF） | IP 校验、协议白名单、重定向复检、域名白名单（§4.1.4） |
| 公有池被刷 | 匿名默认关闭；开启时 IP 限流 + 验证码；用户日配额；用户/IP 兜底限流 |
| 恶意插件 | 沙箱隔离、权限声明制、资源限制、返回值不可信标记、无对话明文访问权 |
| 越权访问私有 Key / 他人对话 | 强制 owner 校验；管理员接口独立中间件；无对话明文管理入口 |
| 提示词注入（经插件/网页） | 不可信内容边界包装；系统提示声明工具输出不可作为指令 |

## 10. 部署架构

```
浏览器 ──HTTPS──▶ API 服务(鉴权·调度·转发·加解密) ──▶ Redis(限流/配额/熔断)
                      │
                      ├─▶ PostgreSQL(api_keys密文 / messages密文 / 审计)
                      ├─▶ 插件沙箱进程（隔离，无 Key 与对话明文访问权）
                      └─▶ 上游 LLM（经 SSRF 校验）
```

- 第一版：单实例 + Redis + PostgreSQL。
- 多实例路径：Redis 共享限流与配额状态；档 C（KMS）解决主密钥一致性；会话改无状态 JWT。
- 加解密为 CPU 轻量操作（AES-NI），不构成水平扩展瓶颈。

## 12. 验收标准（摘要）

1. 数据库导出文件中 grep 不到任何明文 API Key 与任何消息明文内容。
2. 管理员无法通过任何接口获取用户私有 Key 明文或他人对话明文（含越权测试用例）。
3. `169.254.169.254` 等内网目标 100% 被拦截，含重定向场景。
4. 六维限流独立生效；超限返回 429 并指明维度；用户日配额跨 Key 正确累计。
5. 私有池全不可用且开启回退时：请求成功、审计记录 `fallback_to_public=1`、前端弹窗提示。
6. 全局插件用户端无禁用入口；插件生效状态符合"全局 > 用户组 > 个人 > 默认"优先级链。
7. 插件沙箱内尝试读取环境变量 / 网络越权 / 访问对话明文 / 超内存均被拦截。
8. 档 A 下：正确口令可解锁；任一恢复码可重置口令且旧码全部作废；连续错误口令触发锁定。
9. 加密会话的搜索命中正确，且盲索引表中无法还原任何明文关键词。
